# 共享留言墙

留言数据现在由 Node 服务保存到 `ADMIN_STATE_DIR/wall.json`，不是访客浏览器。前台每 2.5 秒读取当前墙面；后台「留言墙」支持按类型筛选、分页预览与删除。站点概览和统计 API 也包含墙面总数、可见数量、已删除数量及涂鸦/刻画/纸条/贴纸分类数量。

## 部署

- 同域：将 `/api/wall` 和 `/api/wall/*` 转发至 Node 服务，静态页面照常部署。前台默认使用 `/api/wall`。
- 跨域（包括 GitHub Pages）：后台设置填写 `https://studio.example.com/api/wall`，构建并部署静态页面；服务设置 `WALL_ORIGINS=https://blog.example.com`，多个 Origin 逗号分隔。
- Node 服务对外监听仍要求 `ADMIN_PUBLIC_ORIGIN=https://studio.example.com`，通过 HTTPS 反向代理保留 Host。管理员 `/api/v1/*` 保持登录保护，不要公开管理口令。
- 本机 `npm run admin` 默认 5174，前台 5173 可访问；后台 `/site/#/guestbook` 直接连同一服务。
- 将整个私有状态目录备份到持久化磁盘，避免部署容器重建时丢失。

未配置可达服务时，前台显示连接错误及重试入口，不会偷偷退回本机保存。旧版 `stacktao-paper-wall-v1` 浏览器数据保留，但不自动上传；本次没有实现批量迁移，避免把此前私有测试留言公开。

## 身份、占位与并发

访客首次打开获得随机匿名令牌，保存在该浏览器的 localStorage；服务端仅保留其哈希作为所有权。不同访客可读取公开留言，只能修改/移动/删除自己创建的内容。清除浏览器存储或更换设备后不能找回匿名所有权；管理员仍可管理。令牌不包含个人资料。

每面墙最多 24 处完成留言。开新墙在服务端串行处理，优先复用空墙，防止同时创建重复空墙。墙名使用服务端固定种子，全体访客一致。客户端只下载当前墙的笔迹与墙册数量，后台每页 20 条。

绘画在本地即时渲染，不等网络才画出每一笔；约 250ms 批量申请占位，4 秒续期，15 秒过期。打字/贴纸编辑也会占位。空间使用 1000 单位宽的墙坐标和 8 单位网格，按笔迹覆盖格子，纸条与文字使用其实际区域；并非整块涂鸦外接矩形。临近笔迹有小幅保守边界。

最终提交必须经过服务端再次验证：容量、其他创作者占位、已保存的笔迹范围、所有权与 revision。两人同时提交重叠区域只有一个能成功，另一个保留本地草稿并提示调整；不自动覆盖，也不会伪装为已保存。短时离线后重新提交重新校验。刷新/关闭页面的未提交手绘仍会丢失，离开提醒保留。

服务端通过队列串行写入、临时文件原子替换和进程写锁保证单实例并发一致性。**当前是单 Node 实例、文件持久化实现，不能横向多实例写同一目录**。若未来访问规模需要多节点，应将相同 API 迁到事务数据库和共享租约存储。实例重启会释放创作中的占位，已保存留言和删除档案保留。

## 管理与删除

管理员删除需要二次确认和 revision 校验。内容从公开列表移除后，活跃访客下一次同步（约 2.5 秒）更新；正在编辑的旧稿不能复活管理员已删除的记录。管理员删除保留在 `wall.json` 的 `deleted` 档案中，后台切换“显示 → 删除档案”可恢复到原位置。恢复重新检查版本、容量、笔迹与租约冲突；冲突时继续保留档案，不覆盖任何现有内容。

访客自己删除可使用页面上的“恢复刚才的痕迹”，恢复仍会检查容量和空间冲突。不能恢复管理员删除的内容。

公开入口具有请求大小、数据类型、文字长度、笔画数量、坐标、来源白名单和每分钟速率限制。匿名身份与这些限制不能替代强反滥用机制；大规模公开运营可在反向代理增加独立限流或验证码。

## API

| 接口 | 作用 |
|---|---|
| POST `/api/wall/session` | 获取匿名访客令牌 |
| GET `/api/wall?section=0` | 当前墙留言、墙册数量、占位、统计 |
| POST `/api/wall/leases` | 提交/续期空间占位 |
| DELETE `/api/wall/leases/{id}` | 释放自己的占位 |
| POST `/api/wall/notes` | 新建或修改，修改带 revision，自由绘画带 lease |
| DELETE `/api/wall/notes/{id}` | 删除自己的留言，带 revision |
| POST `/api/wall/notes/{id}/restore` | 恢复自己的刚删除留言 |
| POST `/api/wall/walls` | 服务端分配下一面空墙 |
| GET `/api/v1/wall?page=1&type=ink` | 管理员分页、分类、统计 |
| DELETE `/api/v1/wall/{id}` | 管理员删除，带 revision |
| GET `/api/v1/wall?deleted=1` | 管理员查看删除档案，支持 page/type 筛选 |
| POST `/api/v1/wall/{id}/restore` | 管理员恢复档案，带 revision |

公开写接口需要允许的 Origin 和访客 Bearer 令牌，管理接口需要管理员会话（初始化前兼容初始化凭据）；普通内容 API 令牌不能管理留言。公共读接口不返回所有权哈希，只返回当前访客是否拥有该留言。

### 整墙管理与命名（2026-10-23）

- 后台「共享留言墙 → 墙面管理」支持删除整墙；「显示 → 删除档案」支持整墙恢复。随墙移除的留言保留，恢复时沿用原墙编号、名称和坐标；之前单独删除的留言不会被意外恢复。
- `GET /api/v1/wall` 同时返回 `walls`（`id/name/count/revision`）和 `deletedWalls`。管理员通过 `DELETE /api/v1/wall/walls/:id` 提交对应墙的 `revision`，通过 `POST /api/v1/wall/walls/:id/restore` 恢复。访客不能调用管理接口。
- 删除在同一写入队列中校验留言版本与未过期的创作占位；冲突返回 409。删除最后一面墙会原子创建新的空墙。浏览中的访客自动跳到有效墙面；离线草稿不会被清除，原墙被删除时须恢复墙面后提交。
- 「开新墙」每次明确创建新编号，不再复用之前的空墙。`nextWall` 保存在持久状态中，删除后及重启后均不复用编号。
- 共享墙名称统一由服务器提供。原有前 256 面墙名称保持稳定，之后扩展为四字、五字与较长的意境名称，不循环原来的三字题名。测试覆盖三个种子的前 100,000 个名称互不重复。极远期超出扩展词库后会加唯一序号，避免声称有限词库能够无限生成不同短词。

### 缩略图墙册（2026-10-23）

墙册按「已有痕迹」「空墙」分组，空墙默认折叠（当前正位于空墙时展开）。每张卡片显示墙名、按 24 条上限计算的剩余留言数、使用量和整墙 SVG 概览；满墙仍可浏览。缩略图按保存的 frame/worldBox 坐标绘制笔迹、纸条、文字与贴纸，文字排版及材质是缩略示意，不代替实际墙面的碰撞检测。

其他墙的预览按可见区域延迟加载，以墙 revision 缓存；读取现有公开接口但不改变 SharedWall 的当前 section、notes 或草稿。选墙在请求成功后更新当前墙，连续点击以最后一次为准。底部「去这面墙留言」回到选定墙，空墙无需新建即可直接使用；原有按留言定位功能保留。
