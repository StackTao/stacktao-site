# 简历页与 PDF

## 使用

- 页面：`/#/resume`；后台：`/admin/#resume`。
- 后台填写姓名、目标岗位、简介、联系方式以及各栏目下的经历。成果每行一条，支持增加和移除栏目、条目。
- 点击「保存并构建」后，网页与 PDF 由同一份内容更新。空姓名不允许保存。
- 示例内容由用户授权用于设计预览；默认 `draft: true`，网页和 PDF 都有「示例」标记。换成真实信息后，将内容状态切换成正式简历。
- 点击「导出 PDF」调用浏览器打印。选择「另存为 PDF」、A4、100% 缩放，关闭浏览器页眉页脚。正文是文字，不是截图，链接可点击。
- 网页使用宽幅个人工作台布局，手机改为单栏阅读；纸面预览和打印恢复 A4 排版。较长内容自动分页，不通过裁切或缩小全文塞进一页。

## 数据与接口

简历保存在现有持久化 `content.config.json` 的 `resume` 字段，随内容目录备份。没有配置姓名时不生成简历路由，也不添加页脚入口；不会凭空发布默认个人资料。

后台复用 `GET/PUT /api/v1/settings`，需要现有登录或具有 `settings:write` 权限的令牌。先 GET 取得完整配置及 revision，在保留其他字段的前提下修改 `resume`，再 PUT 完整配置并带 `If-Match: <revision>`。并发修改返回 409，避免覆盖他人的设置。

```json
{
  "draft": true,
  "name": "苏",
  "role": "目标岗位",
  "monogram": "SU",
  "updated": "2026.10",
  "summary": "个人简介",
  "contacts": [{ "label": "邮箱", "url": "mailto:hello@example.com" }],
  "sections": [{
    "title": "工作经历",
    "caption": "EXPERIENCE",
    "items": [{
      "title": "公司 · 职位",
      "period": "2023 — 至今",
      "subtitle": "职责范围",
      "url": "",
      "points": ["完成了什么，产生了什么结果。"]
    }]
  }],
  "footer": "保持好奇，把事情做好。"
}
```

字段按纯文本输出，链接仅允许 HTTP(S) 与 mailto。正文使用本地 Noto Sans SC 分包字体（OFL），标题沿用本地霞鹜文楷；打印前等待字体就绪。没有把简历发送给第三方 PDF 服务。

## 交互网页版本 · 2026-10-23

网页采用「个人工作台」的表达：放大的文楷姓名、可操作的界面小样，以及始终展开的时间线正文。拖动原生滑杆可以在「线框、结构、细节、成品」之间连续变化；可以重播，也支持键盘。没有自动循环动画。章节和时间索引定位并聚焦到对应内容；邮箱复制有成功和失败反馈。离开页面会停止动画并解除监听；遵循减少动态效果偏好。

「纸面预览」切换回 A4 文档视觉，返回时恢复阅读位置。PDF 只使用专业文档排版，不包含小样、导航与交互控件；两种视图共用同一份后台内容。

## 项目旁注版本（当前）

移除通用界面小样，改为与具体经历绑定的项目旁注。当前围绕留言墙实际开发中的多人冲突、草稿保留与跨设备坐标问题，展示「问题 / 取舍 / 验证」。读者可以点击或用左右方向键、Home/End 切换，直接定位对应经历或打开作品。正文保持全部展开；切换仅使用短暂淡入，遵循减少动态效果偏好。

在后台「简历 → 对应经历 → 网页项目旁注」填写；全部留空不展示。数据位于该经历的 `caseStudy`，字段为 `problem`、`decision`、`result`、`url`，通过现有设置 API 一起保存。旁注只在网页出现，PDF 不新增任何文字或页面。示例工作经历仍需替换，没有把项目经历推断成任职经历。
